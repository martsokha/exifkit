# Architecture

Status: draft

## Goals

1. **Correct.** Follow CIPA DC-008 3.0 and TIFF 6.0, with quirks handled
   explicitly and documented. Reading and then writing an unmodified file
   reproduces the Exif data byte-for-byte when possible, and always keeps
   every value the same.
2. **Robust on hostile input.** No panics, no hangs, and memory use that
   grows at most linearly with input size. Fuzzed in CI. Malformed data
   produces *diagnostics* and a best-effort partial result, not a failed
   parse.
3. **Read and write for every common container.** JPEG, TIFF (and
   TIFF-based raw files for reading), PNG, WebP, HEIF/HEIC/AVIF and
   JPEG XL. Writing changes only the metadata segment and copies every
   other byte through untouched.
4. **Preserve what we don't understand.** Unknown tags, unknown types,
   MakerNotes, SubIFDs and padding all survive a round-trip.
5. **Small and modular.** Zero dependencies by default. Each container,
   and each heavier feature, sits behind a Cargo feature.
6. **An API with no surprises.** Tag identity is separate from tag value.
   Values are stored exactly (no `f64` rationals). Typed accessors return
   `Result`/`Option`, never panic. Errors are a matchable enum.

## Non-goals (v1)

- Decoding or encoding image pixels, and colour management.
- Parsing XMP or IPTC. We find the blobs and preserve them, and expose
  them as raw bytes. A later companion crate can parse them.
- Interpreting MakerNotes (vendor tag tables). They are preserved as
  opaque data, and the API leaves room to add parsing later.
- BigTIFF, and writing to raw formats (CR2, NEF, ARW, DNG). Reading their
  Exif works through the TIFF reader.
- Video containers (MOV/MP4 `udta`/`meta` Exif). Possible later, since
  HEIF already brings an ISOBMFF reader.
- `async` I/O. The parser works on `&[u8]` and container scanning works
  on `Read + Seek`, so async callers can buffer first.

## Layering

```
┌────────────────────────────────────────────────────────────────────┐
│ container::{jpeg, png, webp, heif, jxl, tiff}                      │  find/replace the Exif payload in a file
│   Container trait: locate(&mut R) -> Located; splice(src, dst, new) │
├────────────────────────────────────────────────────────────────────┤
│ Exif (owned model)   ── typed view: tag::*, value::{DateTime, Gps, …}│  edit layer
├────────────────────────────────────────────────────────────────────┤
│ encode: layout planner + serializer                                │  write layer
├────────────────────────────────────────────────────────────────────┤
│ tiff::Reader<'a> (zero-copy over &'a [u8])                         │  parse layer
│   Header, IfdRef<'a>, RawEntry<'a>, bounds-checked Cursor          │
└────────────────────────────────────────────────────────────────────┘
```

- **Parse layer (`tiff`).** A zero-copy, lazy walker over a TIFF block
  held as `&'a [u8]`. It allocates nothing beyond the visited-offset set.
  This layer is public, so a tool that only needs `Orientation` can read
  it without building the owned model, and it is the layer we fuzz most.
- **Owned model (`Exif`).** Built from the parse layer. It owns its
  values (`Vec`/`Box<[u8]>`), stores both the IFD tree and the original
  offsets for every blob, and is what callers edit.
- **Write layer (`encode`).** Turns `Exif` back into a TIFF block. Has a
  *preserve layout* mode and a *compact* mode. See
  [`writing.md`](writing.md).
- **Containers.** Each image format knows how to find the Exif payload
  (an offset and length into the file, plus any prefix such as `Exif\0\0`
  or the 4-byte HEIF/JXL header offset). Each also knows how to write a
  new payload by splicing it in, rewriting only the container structures
  that change (segment lengths, chunk CRCs, box sizes, `iloc` extents,
  RIFF size).

## Tag table

- **Source:** `data/tags.toml`, hand-maintained from the CIPA tables,
  with an ExifTool cross-reference for names and aliases. The file header
  documents the schema. `[[enum]]` tables define value enums once, and
  `[[tag]]` rows refer to them by name, so `FocalPlaneResolutionUnit`
  and `ResolutionUnit` share one enum. Rows that still need checking
  against the CIPA PDF have `verified = false`, and codegen lists them.
- **Validation:** `xtask` rejects duplicate ids, names, aliases and
  constants, unknown enum references, enums on non-integer tags, unused
  enums, pointers without a target, and the reserved `Other` variant.
- **Generation:** `cargo xtask codegen` writes
  `src/tag/generated.rs` and `src/tag/enums.rs`, formatted with nightly
  rustfmt (the formatter CI uses), and the output is committed. There is **no `build.rs`** and no proc-macro, which keeps
  compile times low and the generated code visible in review. CI fails
  if the committed output is stale.
- **Shape of the generated code:**
  - `Tag` is a `Copy` newtype, `Tag { ns: Namespace, id: u16 }`, with
    associated consts such as `Tag::ORIENTATION` and
    `Tag::DATE_TIME_ORIGINAL`.
  - `Tag::info(self) -> Option<&'static TagInfo>` does a binary search
    in a static slice sorted by `(namespace, id)`. `Tag::from_name` does a
    binary search in a sorted index of spec names and ExifTool aliases.
  - Value enums such as `Orientation` and `MeteringMode` are
    `#[non_exhaustive]`, each with an `Other(u16)` variant so that
    unknown values round-trip.

- The crate is `no_std + alloc` when `std` is off. The parse layer, the
  model, the tags and the encoder need only `alloc`, which also makes
  WASM use simple.
- **No `log` dependency.** Diagnostics are returned to the caller. See
  [`api.md`](api.md#diagnostics).

## Safety model

The parser follows these rules, and fuzzing (see
[`roadmap.md`](roadmap.md)) checks them:

1. **`#![forbid(unsafe_code)]`.**
2. **No indexing, `unwrap` or `expect` on data from the input.** All
   reads go through `Cursor`, which returns `Result`. Clippy lints:
   `indexing_slicing`, `unwrap_used`, `expect_used`, `panic`,
   `arithmetic_side_effects` (denied in `tiff/` and `container/`; use
   `checked_*` or `saturating_*`).
3. **Every allocation is checked against the remaining input first.**
   `count × size` uses `checked_mul` and must be `≤ input.len() −
   offset` before any `Vec` is created. The total allocated while
   building the model is capped at `Limits::max_alloc` (default: 4 ×
   input length + 64 KiB).
4. **The graph walk always terminates.** A visited set of IFD offsets
   catches cycles in both the next-chain and the sub-IFD pointers. The
   walk is an explicit stack with a depth cap (`Limits::max_depth`,
   default 8), never recursion. Every entry also charges its in-memory
   size against `Limits::max_alloc`. Without that, overlapping IFDs could
   multiply a small input into many entries. Caps also apply to the number of IFDs
   (default 256), entries per IFD (default 4096) and SubIFDs per IFD
   (default 64).
5. **Partial results.** When a sub-IFD is broken, it is recorded as
   `IfdState::Truncated` or `IfdState::Invalid` along with a diagnostic,
   and the rest of the tree is kept. Only a broken TIFF header, or a
   broken IFD0 in strict mode, is a hard error.
6. **Container scanners also follow these rules.** Segment and box
   lengths are checked, a JPEG scan stops at SOS, and ISOBMFF nesting
   depth and box count are capped.

## Crate conventions

- Crate name `exifkit` (`exif` on crates.io is an abandoned libexif
  wrapper). The repository directory stays `exif`.
- Edition 2024, MSRV 1.95. CI pins the toolchain to the MSRV, as
  `bentoml` does. License MIT, matching the repo `LICENSE`.
- `rustfmt.toml` matches `pgtrgm`: `group_imports = "StdExternalCrate"`,
  `imports_granularity = "Module"`.
- Public enums are `#[non_exhaustive]`. Structs that callers construct
  have builders or `Default`.
- Every public item has a doc comment, and examples are doctests that
  run in CI against fixtures in `tests/fixtures`.
- `deny.toml` follows the other crates.
